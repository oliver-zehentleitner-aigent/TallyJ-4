    Internationalization and RTL

    Locale file shape (t / s / w), unwrap, and AI overwrite rules are in i18n-rich-entries.md.

    Document dir is set with lang

    Id: b9a79126-8a25-4cea-8dd9-07db906c0564
    Type: decision
    Status: active
    Evidence: confirmed
    Source: issue #299 (Bahazid Aref v4 Beta review); frontend/src/locales/localeDirection.ts
    Revisit when: Element Plus ships a first-class app-wide RTL theme we adopt, or a third RTL locale is added

    :lang(ar) / :lang(fa) already set direction: rtl in CSS. That is not enough for UA chrome, screen readers, or Element Plus physical margins (collapse arrows still used margin-left: auto). setLocale now writes both lang and dir on <html>.

    Public/voter pages wrap in ElConfigProvider :direction so Element Plus on those routes follows the same writing direction. The full element-plus/theme-chalk/rtl.css sheet is not imported — that would restyle teller/dashboard surfaces that #299 did not ask to reopen.

    Rejected alternative: hard-code LTR on the voting FAQ or flag row. The review asked for a mirrored layout, not a one-off exception.

    Rejected alternative: import Element Plus RTL CSS globally. Out of scope for this public/voter layout pass and would shift teller tables and dialogs without a dedicated check.

    Version label: one string, no Beta weight span

    Id: 00815d97-922d-4b4d-884c-35d9964bac53
    Type: decision
    Status: active
    Evidence: confirmed
    Source: issue #299; maintainer follow-up — do not give “Beta” a different font weight
    Revisit when: Arabic (or other locales) should also switch from Latin Beta

    common.versionDisplay is rendered as a single $t(...) string. There is no .version-beta span and no Latin-stack/semibold override for the word Beta.

    Persian is نسخه 4 بتا (Bahazid’s wording, no guillemets). Other locales, including Arabic, still use Latin Beta. A full Persian rewrite stays parked.

    Superseded 2026-09: isolating Latin Beta into .version-beta to force a consistent weight. Glen does not want Beta at a different weight.

    Rejected alternative: change Arabic in the same pass. Glen asked for Persian specifically.

    Public dark header text is a narrow token fix

    Type: decision
    Status: active
    Evidence: inferred
    Source: issue #299 dark-mode note; #285 owns the designer pass
    Revisit when: #285 retunes public/voter dark surfaces

Other public/voter contrast (flag chip, test-only banner hardcoded oranges, Element Plus body copy) stays under #285.
